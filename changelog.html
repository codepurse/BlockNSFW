1.7.5 Current August 2026
New
Blocked search results are removed, not papered over
Every blocked result used to be replaced with a large card carrying the extension's logo and a BLOCKED badge. That was bearable for two results in ten and became a wall once image and video results started being filtered too. Blocked results are now simply removed, and one line above the results accounts for them: "3 results blocked by BlockNSFW" — one line however many were blocked. Image and video results just go; a gap in a grid reads as fewer results, while a grid of placeholders reads as an error. Reported by a user moving over from uBlacklist.
You choose what a blocked result leaves behind
Settings → Customization → Blocked Search Results. Keep the quiet removal, or pick Show a notice in place to bring the old per-result card back for web results — a removed result is indistinguishable from one that never existed, and that per-position evidence is the point in an accountability setup. A second switch turns the summary line off entirely. Image and video results are always removed either way.
A count of what was blocked
Nothing outside the page ever showed the extension was working. The toolbar icon now carries the number of things blocked in that tab — search results, filtered images — capped at 99+, and cleared when you navigate. If you would rather have it in the page, Where To Show The Count offers a small floating pill in the corner instead. Clicking the pill lists the sites the blocks came from, busiest first. Those listed sites are plain text: they are not links and lead nowhere.
Follow blocklists other people maintain
Settings → Customization → Subscribed Lists. Give it the address of a ruleset file and BlockNSFW downloads it, blocks everything on it alongside your own entries, and checks for changes once a day. When the author adds new sites, you get them without doing anything. uBlacklist ruleset files work as they are, so addresses you already follow there can be pasted straight in, and one-click subscribe buttons on list authors' sites open Settings with the address filled in ready for you to confirm. A subscribed list can only add blocks. It can never whitelist a site, unblock anything, or change a setting. Turning one off asks for your PIN. Requested by a user.
Comments in your lists
A line starting with # or ! is now a note rather than an entry, in all three boxes — blocklist, blocked words and trusted sites. Both markers work because the tools people arrive from disagree: uBlacklist uses #, uBlock Origin and AdGuard use !. Notes stay attached to the entry written below them when the list is sorted, so they work as section headings, and they survive Import and Export. To block a word that genuinely starts with one of those characters, put a backslash first — \#nsfw. Any such entry already in your list was converted for you, so nothing you saved changes meaning. Requested by a user.
A nudge to pin the extension
Chrome tucks unpinned extensions behind the puzzle-piece menu, which hides the icon, the count on it, and the quickest route to unblocking a site. Settings now shows a dismissible reminder of how to pin it — and only when it is genuinely unpinned.
Fixed
AI image blocking never worked on Firefox
Turning the beta on did nothing on Firefox: no image was ever checked and none was ever blurred. Firefox and Chrome run an extension's background code in two different kinds of container, and the step that loads the image model only ever worked in Chrome's — so on Firefox the model was never there to ask. Nothing looked wrong, which is why this went unnoticed for so long: when the model is unavailable the images are shown rather than left as blank holes, so a page with the filter on looked exactly like a page with nothing to block. The model now loads on Firefox too. Chrome and Edge were never affected.
Firefox was matching against a shorter blocklist than Chrome
The same underlying cause, with a quieter symptom. Three pieces of shared matching logic never reached Firefox's background, and each had a smaller fallback it used instead — so Firefox checked addresses against a 27-word list rather than the full one, missed look-alike domains written in other alphabets, and quietly ignored the path on a whitelist entry, meaning allow this one section of a site allowed nothing at all. All three are in place now.
"Unblock this website" whitelisted the extension instead of the site
Used from a blocked page, the popup read the address of the tab it was open on — which is the extension's own blocked page, not the site that was blocked. The entry it saved matched nothing, so the whitelist appeared to accept it while the site stayed blocked, with nothing to explain why. Reported in #26 on Firefox, though the same path affected Chrome and Edge.
DuckDuckGo's Images and Videos tabs were not filtered at all
A blocked word stopped the matching web results, then the same search on the Images or Videos tab showed everything. The filter was looking for parts of DuckDuckGo's old layout that no longer exist, so no result was ever examined. Both tabs are filtered now, along with the rows of thumbnails that appear on the All tab. A blocked image takes its whole tile with it rather than leaving the caption behind.
A search result that arrived late was never filtered
DuckDuckGo builds its results in the browser, row by row, so a row exists for a moment with its title still missing — and it was being marked as already inspected on the way past. Whichever row happened to be slowest was the one that survived. Rows are now re-examined until they are actually readable.
Your own blocked words were ignored in image search
In image results, a word from your own list only counted when the image filter was set to Strict; on Moderate or Lenient the built-in list was consulted and yours was not. A word you typed yourself is an instruction rather than a guess, so it now applies at every level.
"Go Back" on the blocked page did nothing
The button's click was being discarded outright by the extension's own security policy. It works now — and when the blocked page is the only thing in a tab's history, with nothing to go back to, it leaves the page instead of sitting there.
1.7.4 17 August 2026
New
Take BlockNSFW beyond this browser
Android blocks adult sites across your whole phone, not just one browser — get it on Google Play. Desktop Guard (beta) is a native companion app for Windows and Linux that force-installs the extension so the browser's Remove and Disable buttons are greyed out, and re-applies protection if anything tampers with it. Uninstalling needs a password held by a parent or accountability partner — learn more.
Access Code
An optional second lock on top of your PIN. A random code appears and you have to retype it by hand — copy and paste are switched off, and a typo gives you a fresh code. Choose 32, 64, 128 or 256 characters. By default it only guards the big moments (turning blocking off, clearing your PIN), so day-to-day edits stay quick; there's a switch to require it for every change. It isn't about secrecy — it's about giving yourself a minute to think. Under Security.
Sites you block are now blocked as a source of images
Adding a site to your blocklist stopped you visiting it, but its pictures still turned up everywhere else, most obviously sitting in image search results. Blocking a site now hides its results in image search and hides its images wherever they're embedded or hotlinked, and the picture itself is refused before it downloads. Requested by a user.
Blocked sites can be patterns too
Alongside wildcards, the blocklist now takes a regular expression for the address, /example\.(net|org)/, or for the page title, title/Example Domain/. Same syntax as uBlacklist, so lists you already keep will work. Address patterns block before the page loads; title patterns catch it just after.
Blocked words can be patterns
Instead of listing every spelling of a word, write one line that covers them all. Wrap it in slashes to make it a pattern: /p[o0]rn/ catches "porn" and "p0rn", and /escort(s|ing)?/ catches "escort", "escorts" and "escorting". Plain words still work exactly as before. Patterns are checked when you save, so a mistake tells you what's wrong instead of quietly failing, and one slow enough to freeze pages is refused.
Import and export your lists
Your blocklist, blocked words and trusted sites now have Import and Export buttons. Export saves a file you can keep as a backup or open in a spreadsheet; import accepts .csv or .txt and adds to what you already have rather than replacing it. Imported entries appear in the box first, so you can look them over before hitting Save.
Pages no longer freeze while loading
On Firefox especially, opening a page could stall for about a second while the extension got itself ready, which felt like the browser had locked up. That pause is gone: on the same test page the longest frozen moment dropped from roughly 1.2 seconds to under a twentieth of a second. The same fix applies to Chrome, and nothing about what gets blocked has changed. Contributed by oathkeeper-dev.
Fixed
Names like "Jerome" are no longer blocked
An adult site name buried inside an ordinary word was being treated as a match, so a news page about Jerome Powell was blocked outright and searching for the name blocked the results. Site names now have to stand on their own to count.
A search engine's own safety filter no longer looks like adult content
On 4get.ca, switching its filter on puts the word "nsfw" in the address, and the page was blocked for saying it while doing exactly what you'd want. Settings in a web address are now read as switches rather than as content.
Your settings are harder to unlock in a weak moment
Some settings could previously be changed without your PIN, including deleting your own blocked words, turning off DNS Protection, and lowering AI strictness. Everything that weakens protection now asks for your PIN first. Adding words, tightening settings and turning protections on stay instant, as they should.
Setting up is quicker and uses less data
A fresh install downloaded the whole blocklist straight away, even though the very same list already ships inside the extension. It now starts from the copy it already has and only fetches an update when one is genuinely due, so setup finishes sooner and costs you several megabytes less.
Tidier lists
Your blocklist, blocked words and trusted sites are now sorted A–Z and de-duplicated when you save, so pasting in a long list no longer leaves a mess.
AI Text Protection now asks for a second opinion
The text AI was flagging ordinary sites such as YouTube, so it no longer blocks a page on its own. A page is blocked only when both its text and an image on it look adult, which means the AI Image Blocker needs to be on for this to do anything. It catches less for now; the model is being retrained.
